# 成就配置详解

## 🎯 什么是成就配置？

成就配置定义了游戏中的成就系统，包括各种成就的解锁条件、奖励机制和成就路径。成就系统为玩家提供目标和挑战。

## 📁 配置文件位置

成就配置在 `public/assets/data/achievements.json` 文件中。

## 🏗️ 成就配置结构

成就配置分为两个主要部分：

```json
{
    "achievements": {
        "成就ID": {
            // 单个成就定义
        }
    },
    "achievementPaths": {
        "路径ID": {
            // 成就路径定义
        }
    }
}
```

## 📝 字段说明

### 成就字段

| 字段 | 类型 | 必填 | 说明 | 示例 |
|------|------|------|------|------|
| `id` | 字符串 | ✅ | 成就的唯一标识符 | `"playtime_master"` |
| `name` | 字符串 | ✅ | 成就显示名称 | `"玩耍时光"` |
| `description` | 字符串 | ✅ | 成就描述 | `"尽！情！玩！个！爽！"` |
| `category` | 字符串 | ✅ | 成就分类 | `"play"` |
| `isMainAchievement` | 布尔值 | ✅ | 是否为主要成就 | `true` |
| `condition` | 对象 | ❌ | 解锁条件 | 见下方说明 |

### 成就路径字段

| 字段 | 类型 | 必填 | 说明 | 示例 |
|------|------|------|------|------|
| `id` | 字符串 | ✅ | 路径的唯一标识符 | `"play"` |
| `name` | 字符串 | ✅ | 路径显示名称 | `"玩耍时光"` |
| `description` | 字符串 | ✅ | 路径描述 | `"作为一个活泼的猫..."` |
| `mainAchievement` | 字符串 | ✅ | 主要成就ID | `"playtime_master"` |
| `subAchievements` | 数组 | ❌ | 子成就ID列表 | `[]` |
| `endCondition` | 对象 | ❌ | 结束条件 | 见下方说明 |

## 🔧 常见修改

### 修改成就名称
```json
// 修改前
"name": "玩耍时光"

// 修改后
"name": "超级玩耍大师"
```

### 修改成就描述
```json
// 修改前
"description": "尽！情！玩！个！爽！收集到所有猫玩具并进行过所有玩耍交互"

// 修改后
"description": "成为最会玩的猫咪！收集所有玩具并体验所有玩耍活动"
```

### 修改解锁条件
```json
// 修改前
"condition": {
    "type": "play_completion",
    "requiredToys": ["squeaky_mouse", "spinning_ball", "cat_rope", "black_sock"],
    "timeLimit": 720
}

// 修改后
"condition": {
    "type": "play_completion",
    "requiredToys": ["squeaky_mouse", "spinning_ball", "cat_rope", "black_sock", "new_toy"],
    "timeLimit": 600  // 减少时间限制
}
```

### 添加子成就
```json
// 修改前
"subAchievements": []

// 修改后
"subAchievements": ["toy_collector", "play_expert"]
```

## ➕ 添加新成就

### 步骤1：定义成就
```json
{
    "achievements": {
        "新成就ID": {
            "id": "新成就ID",
            "name": "新成就名称",
            "description": "新成就描述",
            "category": "play",
            "isMainAchievement": false,
            "condition": {
                "type": "counter",
                "counter": "新计数器名称",
                "value": 5
            }
        }
    }
}
```

### 步骤2：定义成就路径（可选）
```json
{
    "achievementPaths": {
        "新路径ID": {
            "id": "新路径ID",
            "name": "新路径名称",
            "description": "新路径描述",
            "mainAchievement": "新成就ID",
            "subAchievements": [],
            "endCondition": {
                "type": "新条件类型"
            }
        }
    }
}
```

## 🎯 成就分类

### 玩耍类 (play)
- 收集玩具
- 进行玩耍活动
- 体验各种娱乐

### 破坏类 (destruction)
- 破坏物品
- 制造混乱
- 搞破坏活动

### 探索类 (explorer)
- 探索新区域
- 发现秘密
- 冒险活动

### 策略类 (strategist)
- 制定计划
- 设置陷阱
- 准备材料

### 温顺类 (obedient)
- 表现良好
- 不搞破坏
- 讨好主人

## 📊 条件类型详解

### 计数器条件 (counter)
基于游戏中的计数器：
```json
{
    "condition": {
        "type": "counter",
        "counter": "toyCollectionCount",
        "value": 5
    }
}
```

### 完成条件 (completion)
需要完成特定任务：
```json
{
    "condition": {
        "type": "play_completion",
        "requiredToys": ["toy1", "toy2"],
        "requiredInteractions": ["action1", "action2"],
        "timeLimit": 720
    }
}
```

### 破坏完成条件 (destruction_completion)
需要破坏特定物品：
```json
{
    "condition": {
        "type": "destruction_completion",
        "requiredDestructions": ["tv_destroy", "computer_destroy"],
        "timeLimit": 720
    }
}
```

### 探索完成条件 (escape_completion)
需要完成探索任务：
```json
{
    "condition": {
        "type": "escape_completion",
        "balconyAccess": true,
        "neighborFight": true,
        "neighborEscape": true,
        "timeLimit": 420,
        "energyRequirement": 3
    }
}
```

### 温顺完成条件 (obedient_completion)
需要表现良好：
```json
{
    "condition": {
        "type": "obedient_completion",
        "noDestruction": true,
        "greetAtDoor": true,
        "timeLimit": 720
    }
}
```

### 策略完成条件 (trap_completion)
需要设置陷阱：
```json
{
    "condition": {
        "type": "trap_completion",
        "requiredTraps": 3,
        "timeLimit": 720
    }
}
```

### 材料完成条件 (material_completion)
需要准备材料：
```json
{
    "condition": {
        "type": "material_completion",
        "requiredMaterials": ["cardboard_box", "string", "aluminum_foil"],
        "timeLimit": 720
    }
}
```

## ⚠️ 注意事项

### 成就ID命名规则
- 使用小写字母和下划线
- 不能包含空格或特殊字符
- 建议使用有意义的名称
- 例如：`playtime_master`, `destruction_king`, `escape_artist`

### 条件设计原则
- 条件要合理可行
- 避免过于困难或简单
- 考虑游戏平衡性
- 提供足够的挑战性

### 时间限制设计
- 时间限制要合理
- 考虑玩家的游戏时间
- 避免过于紧张或宽松
- 与游戏节奏匹配

### 依赖关系
- 引用的物品ID必须在 `items.json` 中定义
- 引用的动作ID必须在 `actions.json` 中定义
- 引用的计数器必须在代码中实现
- 成就路径的关联要正确

## 🔄 与其他系统的关联

### 与动作系统的关联
动作可以触发成就：
```json
{
    "triggerAchievement": "fish_pickup"  // 在actions.json中引用成就
}
```

### 与物品系统的关联
成就可以要求收集特定物品：
```json
{
    "requiredToys": ["squeaky_mouse", "spinning_ball"]  // 引用items.json中的物品
}
```

### 与场景系统的关联
成就可以要求访问特定场景：
```json
{
    "balconyAccess": true,  // 需要访问阳台场景
    "neighborEscape": true  // 需要从邻居家逃脱
}
```

## 💡 策划建议

### 成就设计原则
1. **目标明确** - 每个成就应该有明确的目标
2. **挑战适中** - 难度要适中，既不能太简单也不能太难
3. **有趣生动** - 成就描述要有趣
4. **多样性** - 提供不同类型的成就

### 条件设计建议
1. **渐进性** - 从简单到复杂
2. **多样性** - 不同类型的条件
3. **关联性** - 成就之间可以有关联
4. **平衡性** - 考虑游戏整体平衡

### 路径设计建议
1. **主题明确** - 每个路径有明确的主题
2. **逻辑清晰** - 路径的逻辑要清晰
3. **选择多样** - 提供多种选择
4. **奖励合理** - 奖励要合理
